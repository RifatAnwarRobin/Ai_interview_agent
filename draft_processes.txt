Structure of the system:
* Superbase for the free authentication process.
* N8N webhook to take input from streamlit.
* Response to the N8N webhook.
* Send response to PSQL node for saving raw data.
* Extract Job Description text from the input and convert to tabular format/vector embedding using LLM/ Minstral OCR API.
* Extracted Format will later be stored in PSQL/VectorDB(chromaDB)
* Make questions based on the formatted data(json/or any other format).
* Later the Evaluation part.

Details of issues:
containers are not on the same usable network for the hostname we are trying to use.

We have these networks:
bridge → Docker’s default generic network
host → host networking
none → no networking
n8n-local_default → a project-specific bridge network, almost certainly created by Docker Compose for our n8n-local stack

What this tells:
Our n8n-local container is very likely attached to:
n8n-local_default
Our interview-postgres container was likely started manually with docker run, so it is probably attached only to:
bridge

That means:
n8n-local cannot reliably reach interview-postgres by container name
because Docker DNS by container name works properly when containers share the same user-defined bridge network

That is why we got:
connection refused or unreachable behavior in n8n

* *FIX*
Need both containers on the same user-defined network.

Since n8n-local_default already exists, the cleanest fix is:
Attach Postgres to n8n-local_default

Run:
docker network connect n8n-local_default interview-postgres

Then verify:
docker inspect interview-postgres

and
docker inspect n8n-local

should see both containers listed under n8n-local_default.
